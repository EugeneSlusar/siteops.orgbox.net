# orgBox SiteOps

Модуль для **1С-Битрикс**: встроенный **MCP-сервер на PHP**, через который ИИ-ассистент (Claude и другие клиенты MCP)
читает и, если разрешено, правит **инфоблоки** сайта: разделы, элементы, свойства.

Один раз устанавливается на сайт, отдельных серверов и Node.js не требует.

> Статус: **0.9.1, ранняя версия.** Протокол, OAuth (код авторизации и Device Flow), защита и обновление покрыты автотестами (236 проверок), а `.htaccess` проверен на настоящем Apache (53 проверки).
> Слой доступа к инфоблокам (`BitrixIblockGateway`) проверить без живого Битрикса нельзя:
> перед рабочим использованием пройдите чек-лист из [docs/VERIFY-ON-SITE.md](docs/VERIFY-ON-SITE.md).

## Что умеет

| Инструмент | Режим | Назначение |
|---|---|---|
| `iblock_list` | чтение | инфоблоки: id, тип, код, название, число элементов |
| `iblock_properties` | чтение | свойства инфоблока и значения списков |
| `section_list` | чтение | разделы с вложенностью |
| `element_list` | чтение | поиск элементов по названию, разделу, активности |
| `element_get` | чтение | элемент целиком: поля, тексты, картинки (адрес, размер), свойства (файлы — с id, адресом, именем) |
| `element_filled_properties` | чтение | только заполненные свойства элемента, с названиями |
| `product_get` | чтение | цены по типам, остаток, остатки по складам, торговые предложения (модуль catalog) |
| `element_update` | запись | изменить поля, свойства (в том числе очистить `[]`/`null`), картинки `PREVIEW_PICTURE`, `DETAIL_PICTURE`, даты `ACTIVE_FROM`, `ACTIVE_TO`, загрузить и удалить файлы файловых свойств; значения перечитываются из базы (с `dry_run`) |
| `element_create` | запись | создать элемент (по умолчанию неактивный) |
| `section_update` | запись | изменить раздел |
| `product_update` | запись | записать цены и остатки (общий и по складам) товара или торгового предложения (с `dry_run`) |
| `cache_clear` | запись | сбросить кеш инфоблока или всего сайта (с `dry_run`) |
| `file_read` | чтение | безопасно прочитать обычный текстовый файл из публичного корня, с нумерацией строк |
| `file_rename` | запись | переименовать один обычный текстовый файл в публичном корне без перезаписи цели |
| `delivery_service_list` / `delivery_service_get` | чтение | службы доставки Bitrix sale, цены и ограничения без конфигураций обработчиков |
| `delivery_service_update` | запись | изменить разрешённую службу доставки: название, активность, описание, цену и срок (`dry_run`, проверка после записи) |
| `delivery_restriction_list/create/update/delete` | чтение/запись | ограничения службы по сайту, сумме корзины и местоположению (`dry_run`, allow-list, проверка после записи) |

**Удалять ничего нельзя**: ни один инструмент не удаляет данные, скрыть запись можно только через `active=false`.

> Для служб доставки запись разрешена только в ID из поля «ID служб доставки» в настройках SiteOps. Ограничения `price`, `site` и `location` применяются штатным модулем `sale` при расчёте заказа. Исключение товаров по свойству/составу корзины требует отдельного обработчика Bitrix и не поддерживается штатными ограничениями этого MCP.

## Безопасность по умолчанию

- После установки всё **выключено**. MCP включается в настройках, доступ — по OAuth-подключению (ссылка + согласие администратора) или по токену (`Authorization: Bearer …`).
- Токен показывается один раз, хранится только его SHA-256. Токен можно отозвать.
- Режим по умолчанию — **только чтение**; инструменты записи в этом режиме клиенту даже не показываются.
- Чтение: переключатель «все инфоблоки» или только перечисленные в списке (при снятой галочке и пустом списке недоступен ни один).
- Запись разрешена **только в инфоблоки из явного списка**.
- Картинка или файл принимается как `{"url": "https://…"}` или `{"base64": "…"}`: тип проверяется по содержимому (JPEG, PNG, WebP, GIF, до 10 МБ; для файловых свойств ещё PDF), имя очищается, загрузка по url — только HTTPS, порт 443, публичные адреса (защита от SSRF).
- Допустимые поля — по белому списку; нельзя менять `IBLOCK_ID`, `ID`, автора и т. п.
- Каждое изменение пишется в штатный «Журнал событий» Битрикса (тип `ORGBOX_SITEOPS`) с прежним и новым значением.
- `dry_run` показывает изменения, ничего не записывая.
- Защита входа: список IP, проверка `Origin` (против DNS rebinding), лимит запросов в минуту, ограничение размера тела.

Подробнее: [docs/SECURITY.md](docs/SECURITY.md).

## Выпуск обновлений

Сайты обновляются кнопкой в настройках модуля из **GitHub Releases**. После изменения кода поднимите версию в `modules/orgbox.siteops/install/version.php`,
допишите `CHANGELOG.md`, слейте в `main` и **выпустите релиз** (`git tag vX.Y.Z && git push origin vX.Y.Z` или Actions → release → Run workflow).
Без релиза сайты нового кода не получат. Подробности: [docs/UPDATES.md](docs/UPDATES.md).

## Установка и подключение

Рекомендуемый способ, особенно для нескольких сайтов на одном Битриксе и для хостингов, где `local/` и `bitrix/` — симлинки:

1. Скачайте `site.ops-X.Y.Z.zip` из [Releases](../../releases) и распакуйте в корень сайта (получится `<корень сайта>/site.ops/`).
2. Откройте `https://ваш-сайт/site.ops/admin/` (администратором): включите MCP и подключение по ссылке, укажите ID инфоблоков.
3. Добавьте `https://ваш-сайт/site.ops/mcp` в Claude: клиент выдаст ссылку, вы входите в Битрикс и нажимаете «Разрешить». Токен вручную не нужен.

Настройки, токен и OAuth-подключения у каждого сайта свои. Пошаговая инструкция с проверками: [docs/QUICKSTART.md](docs/QUICKSTART.md). Есть и классическая установка модулем в `/local/modules` (архив `orgbox.siteops-X.Y.Z.zip`).

Пошагово, с примерами для Claude Code и Claude Desktop: [docs/INSTALL.md](docs/INSTALL.md).

## Обновление

Из админки: **Настройки → orgBox: SiteOps → Проверить обновления**. Модуль скачивает релиз из GitHub Releases,
проверяет SHA-256 и **подпись Ed25519**, делает резервную копию, заменяет файлы и откатывается при ошибке.
Автоматически, без вашего нажатия, ничего не обновляется. Подробнее: [docs/UPDATES.md](docs/UPDATES.md).

## Разработка

```bash
php tests/run.php                 # 236 автотестов, Битрикс не нужен
bash tests/apache/verify.sh       # .htaccess на настоящем Apache (нужны apache2, php-cgi)
php tools/build-release.php dist  # собрать оба архива (модуль и site.ops) и SHA-256
```

Требуется PHP 8.1+ (на CI проверяются 8.1, 8.2, 8.3). Выпуск релиза: тег `vX.Y.Z` (должен совпадать с версией в
`modules/orgbox.siteops/install/version.php`) запускает сборку, подпись и публикацию.

```
modules/orgbox.siteops/   — сам модуль (источник кода для обеих форм установки)
  lib/OrgBox/SiteOps/     — Mcp, Tools, Iblock, Auth, Http, Update, Config, Audit
  install/                — установщик, точки входа (tools/), страницы админки
  admin/                  — страница настроек, пункт меню
standalone/site.ops/      — точки входа (mcp/, admin/, oauth/), автозагрузчик и .htaccess формы «папка site.ops»
tests/                    — автотесты без Битрикса (заглушки вместо базы); tests/apache — проверка на настоящем Apache
tools/                    — сборка и подпись релизов
docs/                     — быстрый старт, установка, безопасность, обновления, проверка на сайте
```
