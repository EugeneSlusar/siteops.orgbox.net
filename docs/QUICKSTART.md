# Быстрый старт

Предполагается, что папка `site.ops` уже распакована в корень сайта (рядом с `bitrix/` и `upload/`).
Подробности и другие способы установки: [INSTALL.md](INSTALL.md).

## 1. Проверьте установку (30 секунд)

```bash
curl -si -X POST -H 'Content-Type: application/json' -d '{}' https://ваш-сайт/site.ops/mcp | head -1
curl -sI https://ваш-сайт/site.ops/lib/OrgBox/SiteOps/Bootstrap.php | head -1
```

Что значит ответ первой команды:

| Ответ | Значение |
|---|---|
| `404` и в теле `{"error":"Не найдено."}` | **Установлено правильно, MCP ещё выключен.** Переходите к шагу 2 |
| `401` | Установлено и MCP включён: всё готово, шаг 3 |
| `404` с HTML-страницей сайта | Папка не там: `site.ops` должна лежать в корне сайта, рядом с `bitrix/` |
| `301` | Не работают правила `.htaccess`: проверьте, что файл `site.ops/.htaccess` на месте и `AllowOverride All` |
| `500` | Хостинг не разрешает директивы из `.htaccess` (`AllowOverride`) или ошибка PHP: смотрите журнал ошибок |

Вторая команда должна ответить `403`: служебные файлы закрыты.

## 2. Включите и настройте

1. Откройте `https://ваш-сайт/site.ops/admin/` и войдите администратором Битрикса.
2. Включите **MCP-сервер**.
3. Включите **Подключение по ссылке (OAuth)** и проверьте **Адрес сайта** (`https://ваш-домен`, без пути; лучше задать явно).
4. В **ID инфоблоков** укажите нужные через запятую. Если не знаете ID: **Контент → Инфоблоки → Типы инфоблоков и инфоблоки**, колонка ID.
   Пустое поле означает «читать любые инфоблоки, писать нельзя».
5. **Режим** оставьте «только чтение».
6. Нажмите **Сохранить**.

Повторите первую команду из шага 1: теперь должен быть `401`.

## 3. Подключите клиент

### По ссылке (OAuth): основной способ

**Claude Code:**

```bash
claude mcp add --transport http siteops https://ваш-сайт/site.ops/mcp
```

Запустите `claude`, введите `/mcp`, выберите `siteops` и **Authenticate**. Клиент покажет или откроет ссылку:

1. Откроется страница вашего сайта «Подключение ИИ-ассистента».
2. Если вы не вошли, войдите администратором.
3. Проверьте адрес возврата и режим, нажмите **Разрешить**.
4. В клиенте `siteops` получит статус connected.

**claude.ai:** Settings → Connectors → Add custom connector, адрес `https://ваш-сайт/site.ops/mcp`. Дальше то же самое.

### По токену (запасной способ)

Если подключение по ссылке не заработало: на странице настроек нажмите **Создать новый токен**, скопируйте его сразу (он показывается один раз) и:

```bash
claude mcp add --transport http siteops https://ваш-сайт/site.ops/mcp \
  --header "Authorization: Bearer sop_ВАШ_ТОКЕН"
```

## 4. Первая проверка (только чтение)

Попросите ассистента, например:

- «Покажи список инфоблоков сайта».
- «Покажи свойства инфоблока с ID …».
- «Выведи первые 10 товаров из инфоблока … и укажи, у каких пустое описание».
- «Найди товары со словом "пилка" в названии».

Если ответ приходит, подключение работает. Сравните цифры с админкой (число элементов, названия).

## 5. Когда будете готовы менять данные

1. **Сделайте резервную копию базы** (Настройки → Инструменты → Резервное копирование).
2. На странице настроек переключите режим на **«чтение и запись»** и убедитесь, что в **ID инфоблоков** перечислены только те, где разрешена запись.
3. Просите ассистента сначала показать изменения: «покажи, что изменится, но не записывай» (инструменты умеют `dry_run`).
4. Проверяйте результат в админке. Каждое изменение с прежним и новым значением пишется в **Настройки → Инструменты → Журнал событий** (тип `ORGBOX_SITEOPS`).
5. Закончив, верните режим «только чтение».

Удалять данные нельзя: ни один инструмент этого не делает; скрыть запись можно, сделав её неактивной.

Что модуль не умеет: менять внешний вид сайта (шаблоны, CSS) и загружать файлы (фото). Это делается отдельно.

## 6. Если не получается

| Симптом | Что проверить |
|---|---|
| Клиент пишет «authorization failed» или не открывает ссылку | Включён ли OAuth и верен ли «Адрес сайта» (https, ваш домен). Откройте в браузере `https://ваш-сайт/site.ops/oauth/.well-known/oauth-authorization-server`: должен быть JSON с `issuer` |
| Клиент не находит документы OAuth | Добавьте фрагмент корневого `.well-known` (INSTALL.md → «Необязательно: корневой .well-known») |
| Страница согласия просит войти, и после входа снова просит | Войдите именно администратором (не обычным пользователем) в этом же браузере |
| После «Разрешить» клиент не подключился | Подключайтесь по токену (шаг 3, запасной способ) и сообщите, какой клиент и на каком шаге остановился |
| `401` при каждом запросе по токену | Заголовок `Authorization` теряется хостингом: передавайте `X-SiteOps-Token: sop_…` |
| Ассистент видит не все инфоблоки | Они ограничены списком «ID инфоблоков» |
| Запись отклоняется | Режим «чтение и запись» и инфоблок в списке; иначе запись запрещена намеренно |

Не нашли причину: пройдите [чек-лист проверки](VERIFY-ON-SITE.md) и пришлите, на каком пункте остановились.
