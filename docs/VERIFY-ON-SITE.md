# Проверка на реальном сайте

Автотесты проверяют протокол, защиту, политику записи и обновление. **Работу с настоящим API Битрикса**
(`BitrixIblockGateway`, установщик, страница настроек) автотесты проверить не могут: для этого нужен установленный
Битрикс. Пройдите чек-лист на тестовом сайте или в нерабочее время. Отметьте, что не сработало, и сообщите.

## 1. Установка

**Если ставите папку `site.ops`:**

- [ ] `https://сайт/site.ops/admin/` открывается после входа администратором; неавторизованному показывает форму входа, а не настройки.
- [ ] `curl -sI https://сайт/site.ops/lib/OrgBox/SiteOps/Bootstrap.php` отвечает **403** (то же для `/site.ops/_updates/`, `/site.ops/version.php`).
- [ ] `curl -si -X POST -H 'Content-Type: application/json' -d '{}' https://сайт/site.ops/mcp` отвечает **401 в JSON** (не 301, не 403, не 404, не 500). Если 500, на хостинге ограничен `AllowOverride`.
- [ ] `https://сайт/site.ops/mcp/` (со слэшем) отвечает так же.
- [ ] На двух сайтах одного Битрикса токен сайта `s1` не подходит к сайту `s2` и настройки не смешиваются.

**Если ставите модуль:**

- [ ] Модуль виден в **Настройки → Настройки продукта → Модули**, установка проходит без ошибок.
- [ ] Появились файлы `/bitrix/admin/orgbox_siteops_settings.php` и `/bitrix/tools/orgbox_siteops/mcp.php`.
- [ ] Пункт «orgBox: SiteOps» есть в меню **Настройки**; страница открывается без ошибок PHP.

## 1а. Подключение по ссылке (OAuth, только `site.ops`)

Это единственное, что нельзя проверить без живого клиента Claude. Проходите на тестовом сайте или в нерабочее время.

- [ ] В настройках включены «MCP-сервер» и «Подключение по ссылке (OAuth)», задан «Адрес сайта».
- [ ] `https://сайт/site.ops/oauth/.well-known/oauth-authorization-server` отдаёт JSON с `issuer` вашего сайта и `code_challenge_methods_supported: ["S256"]`.
- [ ] `claude mcp add --transport http siteops https://сайт/site.ops/mcp`, затем `/mcp` → Authenticate: клиент показывает ссылку.
- [ ] По ссылке открывается страница согласия администратора (неавторизованному предлагается войти). Видны название клиента, адрес возврата, режим и список инфоблоков.
- [ ] «Разрешить» возвращает в клиент, подключение появляется в `/mcp` со статусом connected, `tools/list` работает.
- [ ] На странице настроек в «Подключения (OAuth)» есть эта запись; «Отозвать» закрывает доступ (следующий запрос клиента получает 401).
- [ ] «Отклонить» возвращает клиенту ошибку, подключения не появляется.
- [ ] Если клиент не нашёл документы OAuth: добавьте фрагмент корневого `.well-known` из INSTALL.md и повторите. Сообщите, какой клиент и какой шаг не сработал.
- [ ] В **Журнале событий** есть `oauth.approve` с клиентом и адресом возврата.

## 2. Чтение (режим «только чтение»)

- [ ] Токен создаётся, показывается один раз; в `site.ops/_data/settings.php` (или в `b_option` для модуля) лежит только хэш.
- [ ] `tools/list` возвращает 7 инструментов (`iblock_list`, `iblock_properties`, `section_list`, `element_list`, `element_get`, `element_filled_properties`, `product_get`), без `element_update`, `element_create`, `section_update`.
- [ ] `iblock_list`: число элементов совпадает с админкой.
- [ ] `iblock_properties`: для свойства-списка перечислены значения; файловые свойства помечены `F`.
- [ ] `section_list` и `element_list`: страницы (`page`, `limit`) и поле `total` корректны; поиск `query` находит по подстроке.
- [ ] `element_get`: свойства совпадают с карточкой; для списков показывается текст значения.
- [ ] Неверный токен → 401; без токена → 401; GET → 405.

## 3. Запись (включить режим и один тестовый инфоблок)

- [ ] `element_update` с `dry_run: true` ничего не меняет.
- [ ] `element_update` меняет `NAME`, `ACTIVE`, `PREVIEW_TEXT`; в админке изменения видны, поиск и кеш обновились.
- [ ] Свойство-список: запись по тексту значения; строка/множественное свойство сохраняются.
- [ ] `element_create`: элемент создан неактивным, свойства записаны.
- [ ] `section_update`: изменение названия и кода.
- [ ] `cache_clear` (`scope=iblock`, затем `scope=all`): страницы сайта показывают свежие данные, в Журнале событий есть запись `cache.clear`.
- [ ] Картинка: `element_update` с `PREVIEW_PICTURE: {"base64": …}` на тестовом элементе заменяет файл в админке; `element_get` показывает новые `preview_picture.src` и размеры; старый файл удалён из `/upload`.
- [ ] Картинка по `url` (`https://…`) загружается; `http://`, `https://127.0.0.1/…` и не-картинка отклоняются понятной ошибкой.
- [ ] В **Журнале событий** у записи с картинкой нет содержимого файла, только имя, тип и размер.
- [ ] Множественное свойство-список (например, HIT или SERVICES): `element_update` с `[]` очищает его, `element_get` и админка показывают пусто, `verified: true`.
- [ ] Файловое свойство (множественное, например `MORE_PHOTO`): загрузка `{"base64": …}` и `{"url": …}` **добавляет** файл, прежние файлы остаются; `element_get` показывает `id` файлов.
- [ ] `{"delete": [id]}` удаляет только указанный файл (в админке и из `/upload`), остальные остаются; чужой id отклоняется.
- [ ] Не множественное файловое свойство: новый файл заменяет прежний, старый удалён из `/upload`; PDF в `INSTRUCTIONS` загружается и открывается.
- [ ] `verified: false` и `not_applied` появляются, если запись не применилась (проверьте на свойстве, которое Битрикс не принимает).
- [ ] `element_filled_properties` возвращает только заполненные свойства с названиями; число совпадает с карточкой в админке.
- [ ] `product_get` на простом товаре и на торговом предложении (инфоблок 65): цены по типам и остаток совпадают с карточкой каталога; у товара с предложениями виден список `offers`.
- [ ] `product_update`: базовая цена, дополнительный тип цены, общий остаток и остаток склада записываются, `verified: true`; на сайте с включённым складским учётом общий остаток равен сумме по складам.
- [ ] Цена товара на витрине обновилась после `cache_clear`.
- [ ] Запись в инфоблок **вне списка** отклоняется.
- [ ] В **Журнале событий** есть записи `ORGBOX_SITEOPS` с прежним и новым значением.

## 3а. Торговые предложения (версия 0.11.0)

Только на тестовом сайте: инструменты меняют тип товара и создают элементы в каталоге. Перед проверкой убедитесь, что инфоблоки товаров и предложений разрешены для записи и связаны в модуле catalog (Торговый каталог → Настройки → Торговые предложения).

- [ ] `product_set_type` с `type: "with_offers"` и `dry_run: true` показывает `before: simple`, `after: with_offers` и ничего не меняет (проверьте в карточке каталога).
- [ ] `product_set_type` с `type: "with_offers"` на тестовом товаре: в карточке каталога тип «Товар с торговыми предложениями»; `product_get` возвращает `product_type: with_offers`, `verified: true`.
- [ ] Перевод в `with_offers` товара из инфоблока без связи с предложениями отказывает понятной ошибкой, в каталоге ничего не меняется.
- [ ] `offer_create` с `dry_run: true` показывает `would_create` и `properties.CML2_LINK` = id товара; элементов в инфоблоке предложений не прибавилось.
- [ ] `offer_create` у товара не с типом `with_offers` отказывает с подсказкой про `product_set_type`.
- [ ] `offer_create` создаёт два предложения («Белая», артикул MR-02; «Чёрная», артикул MR-01): элементы неактивны, `CML2_LINK` указывает на товар, `COLOR_REF` и `ARTICLE` записаны, `verified: true`.
- [ ] В админке у товара (Торговый каталог → Торговые предложения) видны оба предложения; `product_get` товара возвращает их в `offers`.
- [ ] В админке предложение отображается как торговое предложение (тип 4); запись в каталоге есть (цена и остаток можно задать в карточке предложения).
- [ ] `product_update` с `id` предложения и `prices: {"BASE": 5500}`, `quantity: 581` (или `stores`): цена и остаток совпадают с карточкой предложения, `verified: true`. Если в инфоблоке предложений нет свойств `MINIMUM_PRICE`/`MAXIMUM_PRICE`, в ответе есть `not_synced` и `note`: это ожидаемо.
- [ ] `product_set_type` с `type: "simple"` у товара с предложениями отказывает (ничего не меняется). После удаления предложений вручную в админке перевод проходит (удаление в админке, инструменты удаления не имеют).
- [ ] Предложение с `properties: {"CML2_LINK": …}` отказывает: свойство связи задаёт только инструмент.
- [ ] Инфоблок предложений, который не разрешён для записи, отказывает до создания элемента.
- [ ] Журнал событий: `ORGBOX_SITEOPS` записи `product.type` и `offer.create` с id и значениями.
- [ ] Витрина: предложения показываются на странице товара, выбор предложения даёт цену и остаток из `product_update`.

## 4. Обновление

- [ ] «Проверить обновления» без релизов отвечает понятной ошибкой, с релизом — предлагает версию.
- [ ] Установка без ключа и без галочки «Без подписи» отклоняется.
- [ ] Установка подписанного релиза проходит, версия в настройках обновилась, резервная копия лежит в `/upload/orgbox_siteops/updates/`.
- [ ] Установка архива с изменённым содержимым отклоняется.

## 5. Окружение

- [ ] Заголовок `Authorization` доходит до PHP (иначе используйте `X-SiteOps-Token` или правило `.htaccess`, см. INSTALL).
- [ ] Модуль «Проактивная защита» Битрикса не блокирует POST на `/site.ops/mcp` (или `mcp.php` модуля) (если блокирует, добавьте исключение для адреса).
- [ ] Включён HTTPS.
