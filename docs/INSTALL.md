# Установка и подключение

Есть две формы установки. Код один и тот же, различается только место и хранение настроек.

| | **Папка `site.ops`** (рекомендуется) | Модуль Битрикса |
|---|---|---|
| Куда | `<корень сайта>/site.ops/` (рядом с `bitrix/`, `upload/`) | `/local/modules/orgbox.siteops/` |
| Архив | `site.ops-X.Y.Z.zip` | `orgbox.siteops-X.Y.Z.zip` |
| Настройки и токен | **отдельные для каждого сайта** (по `SITE_ID`) | общие для всей установки Битрикса |
| Если `local/` и `bitrix/` — симлинки на общую папку | не зависит от них: файлы лежат в уникальной папке сайта | ставится в общую папку, виден всем сайтам |
| Установка | распаковать архив | распаковать + «Установить» в админке |
| Адрес MCP | `/site.ops/mcp.php` | `/bitrix/tools/orgbox_siteops/mcp.php` |
| Страница настроек | `/site.ops/admin.php` | **Настройки → orgBox: SiteOps** |

Выбирайте `site.ops`, если на одном Битриксе несколько сайтов или `local/` и `bitrix/` у вас симлинки.

## Требования

- 1С-Битрикс с модулем «Информационные блоки» (`iblock`), PHP 8.1 или новее.
- HTTPS на сайте. MCP-адрес нельзя использовать по обычному HTTP: токен передаётся в заголовке.
- Расширения PHP: `curl` и `zip` (для обновлений), `sodium` (проверка подписи).
- Apache с поддержкой `.htaccess` (для закрытия служебных файлов; см. ниже про nginx).

## Вариант 1. Папка `site.ops`

1. Скачайте `site.ops-X.Y.Z.zip` со страницы Releases.
2. Распакуйте в **корень сайта** (папка, где лежит `bitrix/`), чтобы получилось `<корень сайта>/site.ops/`:

   ```bash
   cd ~/путь/к/public_html && unzip site.ops-X.Y.Z.zip
   ```

3. Откройте `https://ваш-сайт/site.ops/admin.php`, войдите как администратор Битрикса.
4. На странице настроек:
   - включите **MCP-сервер**;
   - нажмите **Создать новый токен** и сразу скопируйте его (повторно он не показывается);
   - в **ID инфоблоков** перечислите нужные. Пусто = чтение любых инфоблоков, но запись при этом запрещена;
   - режим оставьте «только чтение», пока не проверите работу.
5. **Проверьте, что служебные файлы закрыты** (должен быть ответ 403, а не код):

   ```bash
   curl -sI https://ваш-сайт/site.ops/lib/OrgBox/SiteOps/Bootstrap.php | head -1
   ```

Наружу открыты только `mcp.php`, `api.php` и `admin.php`. Всё остальное, включая резервные копии в `_updates/`, закрывает
`site.ops/.htaccess`. **На nginx без Apache `.htaccess` не работает**: добавьте в конфиг сайта запрет вручную:

```nginx
location ~ ^/site\.ops/(?!(mcp|api|admin)\.php$) { deny all; }
```

Секретов в файлах нет (токен и настройки хранятся в базе), так что даже при ошибке закрытия исходный код ничего не раскрывает,
но закрыть его всё равно нужно.

**Деплой через git.** Папка `site.ops` не относится к вашему репозиторию сайта: она не отслеживается, и скрипт синхронизации
её не трогает. Обновляйте её кнопкой в админке (см. [UPDATES.md](UPDATES.md)).

## Вариант 2. Модуль Битрикса

1. Скачайте `orgbox.siteops-X.Y.Z.zip` и распакуйте в `/local/modules/` (получится `/local/modules/orgbox.siteops/`).
   Если сайт использует `/bitrix/modules/`, распакуйте туда.
2. **Настройки → Настройки продукта → Модули** → «orgBox: SiteOps» → **Установить**.
3. **Настройки → orgBox: SiteOps**: включите MCP, создайте токен, укажите ID инфоблоков.

Если `local/` и `bitrix/` у вас симлинки на общую папку, модуль окажется общим для всех сайтов, а его настройки и токен будут
общими для всей установки. В таком случае лучше вариант 1.

## Заголовок Authorization на Apache/FastCGI

Некоторые хостинги не передают заголовок `Authorization` в PHP. Есть два решения.

1. В `.htaccess` корня сайта до правил Битрикса:

   ```apache
   RewriteEngine On
   RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
   ```

2. Или передавайте токен в заголовке **`X-SiteOps-Token: sop_…`**. Модуль принимает оба варианта.

## Подключение клиентов

Адрес: `https://ваш-сайт/site.ops/mcp.php` (для модуля: `/bitrix/tools/orgbox_siteops/mcp.php`).

**Claude Code**

```bash
claude mcp add --transport http siteops https://ваш-сайт/site.ops/mcp.php \
  --header "Authorization: Bearer sop_ВАШ_ТОКЕН"
```

**Claude Desktop** (через мост `mcp-remote`, нужен Node.js на вашем компьютере): в `claude_desktop_config.json`

```json
{
  "mcpServers": {
    "siteops": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://ваш-сайт/site.ops/mcp.php",
               "--header", "Authorization: Bearer sop_ВАШ_ТОКЕН"]
    }
  }
}
```

**claude.ai (пользовательский коннектор)**: сервер использует токен в заголовке и **не реализует OAuth**,
поэтому подключение через интерфейс claude.ai может не заработать. Это ограничение текущей версии.

## Проверка

```bash
curl -s -X POST https://ваш-сайт/site.ops/mcp.php \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer sop_ВАШ_ТОКЕН' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Ожидается JSON со списком инструментов. Затем пройдите [чек-лист проверки на сайте](VERIFY-ON-SITE.md).

## Несколько сайтов на одном Битриксе

Настройте каждый сайт отдельно: у каждого свой `site.ops/`, свой токен, свой список инфоблоков и свой режим.
Токен сайта `s1` не подходит к сайту `s2`.

## Удаление

- `site.ops`: удалите папку `<корень сайта>/site.ops/`. Настройки останутся в базе (`b_option`, модуль `orgbox.siteops`);
  журнал событий тоже останется.
- Модуль: **Настройки → Настройки продукта → Модули** → «orgBox: SiteOps» → **Удалить**.
