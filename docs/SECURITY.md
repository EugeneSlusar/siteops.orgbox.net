# Безопасность

MCP-адрес открыт в интернет и даёт доступ к данным сайта, поэтому защита устроена в несколько слоёв.

## Что защищено

| Угроза | Мера |
|---|---|
| Доступ без права | Токен `Bearer`; хранится только SHA-256; сравнение через `hash_equals`; отзыв в один клик |
| Перебор токена | Лимит запросов в минуту с IP считается **до** проверки токена; токен — 192 бита случайности |
| Запросы из браузера чужого сайта, DNS rebinding | Заголовок `Origin` отклоняется, если его нет в списке разрешённых |
| Утечка токена из логов | Токен только в заголовках, не в адресе |
| ИИ меняет лишнее | Режим «только чтение» по умолчанию; инструменты записи скрыты; запись только в инфоблоки из списка; белый список полей |
| Необратимые потери | Удаления нет совсем; `dry_run`; журнал с прежними и новыми значениями; `active=false` вместо удаления |
| Подмена подтверждения в потоке устройства (фишинг: вам присылают чужой код) | Код подтверждается только администратором, на странице видны имя клиента, IP запроса и режим сайта; решение принимается POST-запросом с защитой формы; `device_code` и `user_code` хранятся только как SHA-256; код из 8 символов (27 в алфавите, без гласных и похожих знаков), живёт 15 минут, одноразовый; опрос чаще интервала даёт `slow_down`; одновременно не больше 30 ожидающих запросов |
| Перехват кода авторизации OAuth | PKCE (S256, обязателен), код одноразовый и живёт 10 минут, расходуется даже при неудачной попытке; точное сравнение `redirect_uri` с зарегистрированным |
| Открытый редирект на странице согласия | Ошибка с неизвестным клиентом или чужим `redirect_uri` показывается на странице, редиректа на непроверенный адрес нет |
| Подтверждение без ведома администратора, подделка формы (CSRF) | Код выдаётся только в ответ на POST вошедшего администратора с собственным токеном формы (cookie `SameSite=Strict` на пути `/site.ops/` + HMAC в скрытом поле) или со штатным sessid Битрикса; GET ничего не разрешает; страница не встраивается во фреймы. Так же защищены все формы страницы настроек |
| Кража токена обновления | Ротация: каждый refresh выдаёт новый, старый гаснет; повторное предъявление использованного отзывает всю цепочку |
| Токены в базе | Только SHA-256; access живёт 1 час, refresh 30 суток; отзыв кнопкой на странице настроек |
| Расширение прав через OAuth | Токен не содержит прав: режим (чтение/запись) и список инфоблоков проверяются при каждом вызове по настройкам сайта |
| Спам регистрациями клиентов | Лимит запросов, не более 200 клиентов на сайт, неиспользуемые клиенты старше 7 суток удаляются; redirect_uri только `https://` или `http://localhost` |
| Исходный код в публичной папке (`site.ops`) | `.htaccess` закрывает всё, кроме папок `mcp/`, `admin/`, `oauth/`; в файле настроек только хэш токена (и токен GitHub, если задан), `_data/` закрыта, файл начинается со строки-заглушки; на nginx нужно правило из INSTALL.md |
| Смешивание сайтов одного Битрикса | В режиме `site.ops` настройки и токен лежат в файле внутри папки сайта, и таблицы OAuth различают сайты по ключу от пути корня сайта: токен одного сайта на другом не действует |
| Подмена обновления | SHA-256 + подпись Ed25519; без подписи установка запрещена, пока администратор явно не разрешит; запрет понижения версии |
| Вредоносный архив | Белый список путей и расширений, защита от `..`, лимиты размера и числа файлов, резервная копия и откат |

## Чего модуль не делает

- OAuth только для публичных клиентов (без секрета клиента, с PKCE) и только в форме `site.ops`. Динамическая регистрация открыта (так требует спецификация MCP): имя клиента указывает он сам, поэтому на странице согласия показывается адрес возврата. Разрешайте, только если подключение начали вы.
- Статический токен (если создан) остаётся в силе параллельно с OAuth. Храните его как пароль; ненужный отзовите.
- Не ограничивает, что именно ИИ-клиент попросит сделать **внутри разрешённого инфоблока** (создать элемент, переписать тексты).
  Поэтому держите «чтение» по умолчанию, а запись включайте на время работы и для нужных инфоблоков.
- Не защищает от перехвата без HTTPS. Используйте только HTTPS.
- Токен GitHub для приватного репозитория обновлений хранится в настройках модуля в открытом виде.
  Выдавайте токен с правом только на чтение содержимого этого репозитория.
- За прокси или CDN `REMOTE_ADDR` может быть адресом прокси: список IP и лимит запросов тогда бесполезны или вредны.

## Рекомендации

1. Включайте MCP только когда он нужен; после работы переключайте в «только чтение» или выключайте.
2. Перечисляйте в списке только нужные инфоблоки; не добавляйте «Пользователи», заказы и т. п.
3. Периодически просматривайте **Журнал событий** (тип `ORGBOX_SITEOPS`).
4. Ограничьте IP, если у вас статический адрес.
5. Если токен мог попасть в чужие руки, создайте новый (старый перестанет работать сразу) и просмотрите журнал.
