# Обновления

## Как это работает

Кнопка **«Проверить обновления»** на странице настроек (`/site.ops/admin.php` или **Настройки → orgBox: SiteOps**) обращается к GitHub Releases репозитория (по умолчанию
`EugeneSlusar/siteops.orgbox.net`), сравнивает версию и предлагает установить. Модуль **ничего не обновляет сам**:
фоновых агентов и автоустановки нет. Причина простая: автоматическая замена PHP-кода по сети — это риск
для сайта, и решение должен принимать администратор.

При установке:

1. скачивается архив своей формы установки (`site.ops-X.Y.Z.zip` или `orgbox.siteops-X.Y.Z.zip`), `.sha256` и `.sig` (только HTTPS);
2. проверяются SHA-256 и подпись Ed25519; без валидной подписи установка отменяется;
3. архив проверяется (пути, расширения, размеры, версия новее установленной);
4. текущая версия копируется в рабочую папку (для `site.ops` это `site.ops/_updates/`, для модуля `/upload/orgbox_siteops/updates/`) как `backup-<версия>-…`; хранятся 3 последние; папка закрыта `.htaccess`;
5. файлы заменяются (для модуля ещё обновляются копии страницы админки и точек входа в `/bitrix/admin` и `/bitrix/tools`); сама рабочая папка при этом не затрагивается;
6. при любой ошибке прежняя версия восстанавливается автоматически.

После установки обновите страницу (PHP-код при необходимости перечитается через OPcache по таймеру хостинга).

## Настройка подписи (один раз)

Подпись защищает от подмены релиза, даже если кто-то получит доступ к GitHub-аккаунту только на запись релизов.

```bash
php tools/generate-signing-key.php
```

- **Открытый ключ** вставьте в настройки модуля (поле «Открытый ключ подписи») на каждом сайте.
- **Секретный ключ** добавьте в GitHub: *Settings → Secrets and variables → Actions → New repository secret*,
  имя `SITEOPS_SIGNING_KEY`. Нигде больше не храните и никому не показывайте.

Без открытого ключа обновления не устанавливаются. Можно явно разрешить установку только по SHA-256
(галочка «Без подписи»), но это защищает лишь от повреждений при загрузке, а не от подмены.

## Приватный репозиторий

Для приватного репозитория создайте токен GitHub (fine-grained, доступ к одному репозиторию, **Contents: Read-only**)
и введите его в настройках. Он нужен только для скачивания релизов.

## Выпуск новой версии (для разработчика)

1. Поднимите `VERSION` в `modules/orgbox.siteops/install/version.php`, дополните `CHANGELOG.md`.
2. Создайте тег и отправьте его:

   ```bash
   git tag v0.2.1 && git push origin v0.2.1
   ```

3. Workflow «release» проверит, что тег совпадает с версией, прогонит тесты, соберёт **оба архива** (`orgbox.siteops-…` и `site.ops-…`), подпишет их и опубликует релиз.

Теги, не совпадающие с версией, отклоняются. Если секрет подписи не задан, релиз публикуется без `.sig`,
и сайты с настроенным ключом такую версию не установят.
