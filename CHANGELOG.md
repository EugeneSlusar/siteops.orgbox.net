# История изменений

## 0.10.7 — 2026-11-26

- `file_read` поддерживает типовую установку Битрикс, где `<public root>/bitrix` — симлинк на общую папку вне public root. Цель именно этого симлинка становится доступной только для чтения; внешние вложенные симлинки по-прежнему запрещены.

## 0.10.6 — 2026-11-26

- `file_read` разрешает каталоги шаблонов `.default` внутри `bitrix/` и `local/`; другие скрытые сегменты по-прежнему закрыты.
- Промежуточные симлинки каталогов допускаются, только если их разрешённый путь остаётся внутри публичного корня сайта. Симлинки, ведущие наружу, отклоняются.

## 0.10.5 — 2026-11-26

- `file_read` теперь читает разрешённые обычные текстовые файлы во всём публичном корне, включая `bitrix/` и `local/`; фильтры скрытых, служебных и потенциально конфиденциальных данных сохранены.
- `file_rename` запрещён для любых путей внутри `bitrix/` и `local/`: в этих каталогах доступно только чтение.

## 0.10.4 — 2026-11-26

- `file_read` теперь может читать исходники только в двух узких деревьях Maxma: `bitrix/components/maxma/` и `bitrix/modules/maxma.loyalty/`. Любые другие пути внутри `bitrix/` по-прежнему закрыты.
- `file_rename` по-прежнему запрещён для всего `bitrix/`, включая разрешённые для диагностики Maxma пути.

## 0.10.3 — 2026-11-26

- **Новые инструменты MCP для файлов сайта:** `file_read` читает только разрешённые текстовые файлы публичного корня с нумерацией строк; `file_rename` безопасно переименовывает один такой файл без перезаписи существующей цели.
- Защита файловых путей: запрещены абсолютные пути, `..`, нулевые байты, скрытые файлы и каталоги, симлинки, Bitrix-служебные области, `upload/`, кеши, логи, сессии, резервные копии, чувствительные имена и бинарные/секретные расширения. В журнал событий записываются вызов, пути, идентификатор и результат — без содержимого файла.

## 0.10.2 — 2026-11-26

- **Совместимость с OpenCode MCP OAuth:** `/.well-known/openid-configuration` теперь возвращает обязательные для OIDC Discovery поля `jwks_uri`, `subject_types_supported` и `id_token_signing_alg_values_supported`.
- Добавлен публичный JWK Set: `https://ваш-сайт/site.ops/oauth/jwks/`. Документы discovery и JWK Set доступны по CORS и не требуют сессии Битрикс.

## 0.10.0 — 2026-11-18

- **Новое: переключатель «Разрешить доступ на чтение ко всем инфоблокам»** в настройках.
  Галочка включена — чтение доступно по всем инфоблокам, список ID не ограничивает чтение. Галочка снята — читать можно только инфоблоки из списка ID (при пустом списке не доступен ни один).
  **Запись по-прежнему разрешена только в инфоблоки из списка** при любом положении галочки и только в режиме «чтение и запись».
- Совместимость: пока галочка ни разу не сохранялась, работает прежнее правило (пустой список = читать все, непустой = только он). Настройки существующих сайтов не меняются.
  После первого сохранения формы значение задаётся явно.
- Страницы согласия OAuth и подключения по коду показывают, что именно доступно (чтение и запись описаны отдельно).
- 245 автотестов.

## 0.9.2 — 2026-11-18

- **`product_update`: базовая цена дублируется в свойства `MINIMUM_PRICE` и `MAXIMUM_PRICE`.** Если в `prices` есть базовый тип (обычно `BASE`), оба свойства получают цену строкой (`3500`, `90.5`) той же записью, что и цена в каталоге.
  Если свойства в инфоблоке нет, запись отклоняется до изменений. Свойства, которые уже совпадают, не трогаются; если цена верна, а свойства расходятся, они исправляются.
- `product_update` с `verified`: проверка перечитывает из базы и цены, и остатки, и эти свойства. `verified: true` означает, что всё совпало с запрошенным.
- Голое число в `prices` (`{"BASE": 3500}`) принимается, как и объект; тесты проверяют, что результат тот же.
- Описание инструмента `product_update` перечисляет, что именно записывается и в какие поля.
- Внутреннее: `IblockGateway::updateProduct` получил параметры `$iblockId` и `$properties`.
- Автотестов: 240. Запись свойств в Битриксе (модуль catalog и `SetPropertyValuesEx`) проверьте на живом сайте: товар, перечитать через `product_get` и `element_get`.

## 0.9.1 — 2026-11-26

- **Новое: поля `ACTIVE_FROM` и `ACTIVE_TO`** (дата начала и конца активности элемента) в `element_update` и `element_create`.
  На сайтах Aspro Max это, например, дата отзыва или новости на витрине. Формат: «ГГГГ-ММ-ДД» или «ГГГГ-ММ-ДД ЧЧ:ММ[:СС]», пустая строка очищает. Неверная дата отклоняется.
  `element_get` возвращает `active_from` и `active_to` в том же формате. Дата переводится в формат сайта автоматически.
- 236 автотестов. Слой Битрикса (чтение и запись дат) проверьте на живом сайте: docs/VERIFY-ON-SITE.md.

## 0.9.0 — 2026-11-25

- **Исправлено: `element_update` не очищал множественное свойство при `[]`.** Битрикс игнорирует пустой массив, поэтому в ответе было `after: []`, а в базе значения оставались.
  Теперь `[]` (и список из одних `null`) записывается как `null`, что очищает свойство.
- **Ответ `element_update` строится по перечитанным из базы значениям**, а не по отправленным: `changes.<ключ>.after` — то, что реально лежит в базе.
  Добавлены `verified` (`true`, если всё применилось) и, при расхождении, `not_applied` и `expected`. Пустые значения (`null`, `''`, `[]`) считаются равными, порядок значений множественного свойства не важен.
- **Новое: файловые свойства** (`MORE_PHOTO`, `INSTRUCTIONS`, `PHOTO_GALLERY` и др.) в `element_update` и `element_create`:
  `{"base64": "…", "name": "a.jpg"}` или `{"url": "https://…"}` добавляет файл (у не множественного свойства заменяет прежний), список таких объектов добавляет несколько,
  `{"delete": [id файлов]}` удаляет отдельные файлы, можно вместе: `{"add": …, "delete": […]}`. Остальные файлы сохраняются. Очистить свойство целиком через `null`/`[]` нельзя (случайная потеря всех файлов).
  Допустимы JPEG, PNG, WebP, GIF и PDF (тип по содержимому, до 10 МБ). Описание формата добавлено в описание инструмента.
- `element_get` для файловых свойств возвращает описание файла (`id`, `src`, `name`, размеры), а не число: id нужен для удаления. **Формат значений файловых свойств изменился.**
- **Новое: `element_filled_properties`** — только заполненные свойства элемента с названиями, типом и значением.
- **Новое: `product_get` и `product_update`** — цены по типам цен, общий остаток и остатки по складам из модуля catalog (таблицы цен и остатков), список торговых предложений; запись с `dry_run` и перечитыванием.
  Тип цены задаётся id или кодом (например, `BASE`), цена — числом или `{"price": …, "currency": "RUB"}`. Удалять цены нельзя.
- `cache_clear` без изменений (появился в 0.8.0).
- 235 автотестов. Слой Битрикса (файловые свойства, модуль catalog) проверьте на живом сайте: docs/VERIFY-ON-SITE.md.

## 0.8.0 — 2026-11-24

## 0.6.0 — 2026-11-22

- **Новое: подключение по коду (OAuth Device Authorization Grant, RFC 8628)**, как `gh auth login`. Адреса: `POST /site.ops/oauth/device` (старт),
  `/site.ops/oauth/token` с `grant_type=urn:ietf:params:oauth:grant-type:device_code` (опрос), страница подтверждения `/site.ops/oauth/verify/` (вход администратором,
  сверка кода, «Разрешить» / «Отклонить»). Стандартные ответы опроса: `authorization_pending`, `slow_down`, `expired_token`, `access_denied`.
  Выдаются те же токены (доступ 1 час, обновление 30 суток), права определяются настройками сайта. Код устройства и код для человека хранятся только как SHA-256.
- Клиент `tools/device_login.py` (`login`, `token`), токены в файле с правами 600.
- Регистрация клиентов принимает `grant_types` с device_code без `redirect_uris`. Документ сервера объявляет `device_authorization_endpoint`.
- Новая таблица `orgbox_siteops_oauth_device` создаётся сама при первом обращении. Обновление `.htaccess` обязательно (новые адреса `device`, `verify`): кнопка обновления его заменяет.
- 203 автотеста.

## 0.5.1 — 2026-11-18

## 0.5.0 — 2026-11-17

- **Исправлено: настройки со страницы администратора не доходили до публичной части.** В 0.4.0 они хранились в `b_option` «по сайту» через
  `SITE_ID`, а в админке и на публичных страницах он может различаться; галочки могли не сохраняться или не действовать.
  Теперь для `site.ops` настройки лежат в файле `site.ops/_data/settings.php` внутри папки сайта; таблицы OAuth различают сайты по ключу от пути корня.
  Обновление и резервные копии эту папку не трогают, сборка не пропускает её в архивы.
- Страница настроек говорит вслух: не прошла проверка сессии, запись невозможна, значения не сохранились (проверка чтением после записи);
  показывает путь к файлу настроек и можно ли в него писать.
- Убран старый подписанный API (HMAC) и его точка входа `/site.ops/api`: включить его на странице настроек было нельзя.
  При ручном обновлении удалите папки `site.ops/lib` и `site.ops/api` перед распаковкой (см. docs/UPDATES.md).
- Новый документ docs/QUICKSTART.md: что делать после установки.
- 156 автотестов (страница настроек теперь покрыта), 49 проверок на настоящем Apache.

## 0.3.0 — 2026-11-15

- Новая форма установки: **папка `site.ops`** в корне сайта (без регистрации модуля в `local/` и `bitrix/`). Рекомендуется для
  нескольких сайтов на одном Битриксе и для хостингов с симлинками.
- В этой форме токен и настройки **отдельные для каждого сайта** (по `SITE_ID`); служебные файлы закрыты `.htaccess`.
- Релиз теперь содержит два архива: `site.ops-X.Y.Z.zip` и `orgbox.siteops-X.Y.Z.zip`; обновление берёт архив своей формы.
- Рабочая папка обновлений внутри `site.ops/_updates` исключена из копирования и удаления.
- Страница настроек вынесена в общее представление для обеих форм.
- 106 автотестов.
